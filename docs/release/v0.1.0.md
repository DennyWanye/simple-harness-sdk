# Simple Harness SDK v0.1.0 Release Notes

**Release Date:** 2026-08-15  
**Tag:** v0.1.0  
**Status:** Initial SDK Foundation Release

---

## Overview

This is the first release of the Simple Harness SDK, extracting the workflow execution engine and runtime contracts from the Simple Harness product into a standalone, reusable SDK.

**What this release delivers:**
- ✅ Core contracts and execution model
- ✅ Fault-tolerant workflow runtime
- ✅ Three official workflow profiles
- ✅ Conformance testing framework
- ✅ Public API for host implementations

**What this release does NOT include:**
- ❌ Full product integration (deferred to v0.2.0)
- ❌ Production deployment in Simple Harness desktop app
- ❌ Complete adapter implementations

## Workflow Profiles

Three official profiles included:

### 1. `durable_task` (Base Profile)
- Root workflow: task execution with fault tolerance
- Driver: ReAct agent loop
- Supports: tool execution, continuation, terminal delivery

### 2. `personal_v1` (Personal Workflow)
- Profile of durable_task with bounded budget
- Default proposal budget: 40
- Default fix budget: 3
- Use case: personal productivity workflows

### 3. `capability_build` (Builder Profile)
- Profile of durable_task for capability generation
- Constrained budgets for proposal/fix
- Builder contracts for capability lifecycle
- Use case: capability development workflows

## Architecture

### Runtime Kernel
- Fault-tolerant execution with resume/replay
- SQLite-backed context and continuation
- Provider fence for exclusive run ownership
- Tool batch execution with effect policies
- Terminal delivery with acknowledgment

### Workflow Engine
- Profile-based workflow configuration
- Driver abstraction (ReAct, Workflow, custom)
- Child run coordination
- Admission control and authorization

### Testing Framework
- Protocol version 1.0.0 (semantic versioning)
- Host factory pattern for flexible implementations
- Four conformance suites: provider, tool, runtime, workflow
- JSON report output for CI integration

## Known Limitations

### v0.1.0 Scope
1. **Product Integration Deferred**
   - Simple Harness desktop app still uses old harness code
   - SDK adapters not implemented (planned for v0.2.0)
   - No E2E validation with real desktop app

2. **Conformance Tests**
   - Framework exists, test suites partially populated
   - Full suite coverage planned for v0.2.0

3. **Documentation**
   - API reference in source docstrings
   - Consumer handoff docs pending (T7.4)
   - Integration guide for product adapters pending

### Design Constraints
- SQLite required for context persistence
- Python 3.11+ only (no 3.10 support)
- Async-first API (no sync wrappers)

## Migration Guide

### For Product Integration (v0.2.0)

If you're integrating this SDK into the Simple Harness product:

1. **Read T6-STRATEGIC-DECISION.md** - Understand why adapters are deferred
2. **Implement Runtime Adapters** - Bridge product concerns to SDK protocols
3. **Wire Composition** - Use `deskpet.sdk_adapters.composition.build_product_runtime()`
4. **Run Conformance Tests** - Validate adapters with SDK test framework
5. **Switch Ingress** - Replace old harness bootstrap with SDK runtime
6. **Delete Old Authority** - Remove duplicate implementations

See `docs/consumers/product-integration-guide.md` (coming in v0.2.0).

### For New Consumers (AIPhone, etc.)

1. **Install SDK wheel** with hash verification
2. **Implement RuntimePorts** - Provide persistence, tools, providers
3. **Define RuntimeProfile** - Configure workflow profiles
4. **Implement RuntimeDriver** - Custom execution logic (or use ReAct)
5. **Call build_runtime()** - Get configured runtime instance
6. **Run conformance tests** - Validate implementation

See `docs/consumers/aiphone-handoff.md` (coming in T7.4).
