## 2. 构建方式

按 `docs/build-and-release.md`：主工作树保持干净（同期有只读消费者在用），构建在
`git worktree add --detach` 出来的干净分离工作树里做，**一次性**产出，之后不再 `uv build`。

```bash
git worktree add --detach "$BUILD_DIR" a8e902a6ad18ade512fe38830de551819adb323c
cd "$BUILD_DIR" && uv sync --frozen --group dev
uv run --frozen python scripts/build/reproducibility.py --output candidate --planned-tag v0.12.0
```

`reproducibility.py` 在 `SOURCE_DATE_EPOCH=0` 下**连建两次并逐字节比对**，通过后才落盘；
`candidate/` 即冻结发布集：wheel、sdist、`BUILD_INFO.json`、`SBOM.spdx.json`、`NOTICE`、
`SHA256SUMS`、`candidate-manifest.json`（schema `simple-harness-candidate-manifest-v1`）。

同一批字节复制进 `dist/` 后按手册补权威溯源并复验：

```bash
uv run --frozen python scripts/build/authoritative_provenance.py emit   --dist dist --source-commit a8e902a… --build-utc 2026-09-16T20:12:54Z
uv run --frozen python scripts/build/authoritative_provenance.py verify --dist dist --source-commit a8e902a… --version 0.12.0
uvx --from "twine>=6.1,<7" twine check dist/*.whl dist/*.tar.gz
./scripts/verify_release_gate.sh
(cd dist && shasum -a 256 -c SHA256SUMS)
```

## 4. 已知红项与归类（未修改任何门禁脚本）

**`mypy` 17 errors / 4 files —— 基线数字，不是本次引入。**
`plans/2026-09-16-full-target/HANDOFF.md` 从 P1.1 起每一片都记录「mypy 17（基线）」。
16 条是 `evaluation/are_benchmark.py` 找不到可选依赖 `are.simulation.*` 与 `pydantic`
（ARE/AgentDojo 评测栈不在 dev 依赖组里），1 条是 `evaluation/agentdojo_runner.py:383`
的 `Trying to read deleted variable "error"`。两者都在评测适配层，不进 wheel 的运行路径。

**`reuse lint` FAIL —— 长期既有缺口。**
184 个文件没有 SPDX 头且未被 `REUSE.toml` 的 `[[annotations]]` 覆盖，含
`CHANGELOG.md`、`ARCHITECTURE/*.md`、`src/simple_harness/execution/audit.py` 等老文件。
已核对：`REUSE.toml` 在 `a8e902a` 与上一版 `a5c8fca`（0.11.1）**逐字节相同**，
且 `audit.py` / `CHANGELOG.md` 在 0.11.1 时同样没有 SPDX 头 —— 即 0.11.1 发布时这条门禁
就是红的。**替代证据**：许可元数据由 `NOTICE`（`af264702…`）与 `SBOM.spdx.json`
（`4dfa8f7b…`）承载，两者都进了 `SHA256SUMS` 与 `candidate-manifest.json`；
wheel/sdist 的 `twine check` 通过，包内 `License-Expression` 为 Apache-2.0。

**全仓 `pytest -q` 的 18 个收集错误 —— 全部是环境缺口。**
手册第 2 步的裸 `pytest -q` 在本机会被 18 个 collection error 打断（`Interrupted`）：

- 13 个文件用 `@pytest.mark.asyncio`，而 `pytest-asyncio` 不在 `[dependency-groups] dev` 里，
  `--strict-markers` 于是拒绝（`tests/orchestrator/gap_phase1/*` 12 个 +
  `tests/integration/test_shared_capacity_dispatch.py`）。HANDOFF 已记：
  「gap_phase1 需 `--with 'pydantic>=2' --with pytest-asyncio`」。
- 3 个 `tests/integration/runtime/test_context_use_*.py` 缺 `simple_harness_memory`
  （认知记忆 SDK 2026-09-10 已从产品线整条移除）。
- 2 个 `tests/orchestrator/gap_phase1/test_agentdojo_*.py` 缺 `pydantic`。

补上这两个可选依赖后收集恢复正常，数字见下。

### 4.2 本次发布发现的两条真实遗留

**F-REL-1 — `tests/unit/contracts/public-api.json` 的版本戳没跟上 0.12.0。**
快照里仍写 `"version": "0.11.1"`，于是 `test_public_api.py` 的 5 条断言全红。
已逐项核对：`simple_harness.__all__`、`simple_harness.contracts.__all__`、
`simple_harness.runtime.__all__`、`simple_harness.testing.arm64_candidate.__all__`
四个列表与快照**元素与顺序完全一致** —— 公开 API 表面没有漂移，只有版本戳过期。
不影响 wheel 运行路径（快照是 `tests/` 下的夹具）。修法是重生成快照，属下一个提交。

**F-REL-2 — `SDK_DEPENDENCY_LOCK_HASH` 没跟上 `uv.lock`。**
`src/simple_harness/workflow/dependency_lock.py:14` 仍是
`9b1bebc8f2bf…`，而仓库 `uv.lock` 现在是 `44901dce70d6…`。
`uv.lock` 最后一次变更在 `e80cfa8`（共享本地模型容量那一片），常量未同步。
这个常量会被 `compile_workflow(..., dependency_lock_hash=...)` 印进编译出来的 Workflow，
即一条**现在不成立的依赖身份声明**。不影响装载与执行，但发布前应当修。
该用例在 0.11.1 基线上是绿的 —— 这条确实是本轮引入的。

### 4.4 一条环境陷阱：不要给全仓跑加 `pytest-asyncio`

为了让 gap_phase1 能收集而加上 `--with pytest-asyncio`（1.4.0）之后，本机出现**永久挂起**：

- `tests/integration/test_shared_capacity_dispatch.py` 单独跑，2 个 F 之后进程停在
  `kevent` 上，>120s 零进展、0% CPU；
- `pytest -q tests/orchestrator` 全量跑到 56% 处同样停死。

所以本次的编排范围门禁用 `--ignore=tests/orchestrator/gap_phase1` 而不是加插件；
gap_phase1 要跑就单独跑、单独超时。

## 6. 消费者须知

- **默认语义未变**：`MissionSpec.orchestration_semantics_version` 默认 `legacy`，
  不传这个字段的调用方行为与 0.11.x 一致（legacy 事件字节 golden、
  allocator/frontier 源码 hash、冻结提示词摘要均未变）。
- **策略快照 digest 变了**：`85d78ea5…` → `7cf60224…`，差异恰好一条
  `config.max_root_review_cuts: null → 3`。全仓没有钉死该 digest 的常量，
  但外部对照脚本要重取基线。
- **分层 Mission 收尾会花两次 mission 账户的模型调用**：根评审人
  （`root_review._ask_root_reviewer`）**加上**既有的 Mission Judge。预算按两次算。
- **PANDA/HDDL 后端在本机是 stub**：没有 cmake/gengetopt；配置 `SH_PANDA_PARSER`
  后真实用例自动启用。
- **L2 `appworld` 谓词的 `app` 参数受 `PUBLIC_READ_APIS` 限制**：非 `supervisor`
  应用的读取返回 `OBSERVER_UNAVAILABLE`（诚实的 UNKNOWN，不是假的 FALSE）。
  G8 修的是「假 FALSE → UNKNOWN」，**没有**放宽白名单。
- **库 schema 版本 18**：迁移 16/17 的校验和逐字节未动；就地升级会留
  `<db>.pre-schema-18.backup`。
