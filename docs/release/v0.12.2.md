## 3. 迁移注意

**默认语义未变。** `MissionSpec.orchestration_semantics_version` 默认仍是 `legacy`。不传这个字段的调用方行为与 0.12.1 一致。

分层模式（`orchestration_semantics_version="hierarchical"`）调用方需要知道：

1. **方法 `@2`。** `code.fix-by-patch` / `code.fix-by-revert` / `code.fix-by-assessed-revert` 升到 `method_version 2`（criterion_links 是契约字节）。旧库 `@1` 行保留并存；点名 `@1` 的新提案按未准入拒绝。Grok runner 的 FREEZE-candidate 必须按本版重生成。另：`code.inspect-changeset@2`、`code.summarize-review@2`（可选 patch）；`code.apply-patch@2` 可选 `tests` 输出、`code.verify-tests@2` 接 tests 输入；种子方法 `code.implement-contract`。
2. **提示词默认版本（旧版字节不动，可 pin）。**
   - Worker：`worker-hierarchical-v4`（v1–v3 可 pin）
   - Planner：`planner-hierarchical-v7`（v1–v6 可 pin）
   - Method synthesizer：`method-synthesizer-v7`（v1–v6 可 pin）
   - Root reviewer：`root-reviewer-v3`（v1–v2 可 pin）
3. **新停机原因（字符串，不改 `MissionStopReason` 枚举）。**
   - `planning_failed`：规划走不下去（含修复受阻、相同验证失败额度用尽）
   - `runtime_unavailable`：provider 交接后连续 UNKNOWN / 鉴权失败，运行时不可用
   - `root_review_repairs_exhausted`：`max_root_review_repairs` 用尽
   - `repeated_verification_failure`：同一 occurrence 连续 N=3 次相同验证失败（经 `PlanningRejected` 升级；终态常落 `planning_failed`，detail 带此理由）
4. **`usage_fully_known`。** `costs_report` 与分层 `final_report` 增加此字段（用量是否全部已知），与 `budget_conserved`（`remaining+reserved+settled==pool`）分开。Host 应用前者，不要把「有未知」等价于「不守恒」。

存储 schema 仍是 18。无新配置项进入策略快照（`max_root_review_repairs` 是 0.12.1 已有字段）。`contracts/` 本版零改动。
