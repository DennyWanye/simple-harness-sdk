# Simple Harness SDK 0.1.1 candidate

This candidate adds the executable consumer conformance protocol and establishes
one runtime/package version authority at `simple_harness.version.__version__`.

## Host compatibility

0.1.1 tightens the Tool authorization contract. `prepare(...)` may return an
immediate decision or a durable `REQUIRE_USER` request, but a Host must now
implement both `bind_decision(...)` and `bind_effect_handoff(...)`. The Host
receipt must bind the SDK receipt hash; without the handoff binder the effect
remains prepared and the physical Tool is not called. A 0.1.0 Host that only
implements `authorize(...)` is not Tool-compatible until these receipt binders
are added.

Official Workflow service groups also validate their required typed operations
at composition time. ReAct start snapshot schema v3 pins the policy fingerprint
before the first Provider or Tool side effect; v1/v2 snapshots remain readable
through the legacy unpinned compatibility path.

Candidate artifacts are built twice from one clean commit with
`SOURCE_DATE_EPOCH=0`. `scripts/build/reproducibility.py` rejects tracked and
untracked changes in the declared wheel/sdist build surface, a non-empty output
directory, a planned tag other than `v0.1.1`, or an existing tag that points at
another commit. The
result directory contains the exact wheel and sdist plus `BUILD_INFO.json`,
`SBOM.spdx.json`, `NOTICE`, `SHA256SUMS`, and `candidate-manifest.json`.

Remote conformance is intentionally not dispatched by the local candidate task.
The prepared workflow accepts an exact commit, artifact run, artifact name,
wheel SHA-256, and consumer Host factory. It installs the same wheel bytes on
macOS ARM64, Windows x64, and Linux ARM64 with Python 3.11; tag and Release
creation remain separately authorized operations.
