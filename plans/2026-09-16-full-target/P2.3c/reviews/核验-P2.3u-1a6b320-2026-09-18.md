## 2. 重点审查

### (a) 快照口径 —— overlay 在绑定之前（P0 候选不成立）；retry 拷贝把产物算进快照（P1）

时序（`_next_attempt` → `_bind_workspace` → `_bind_agent`）：

1. `event_handler.py:8962-8972` 把 P2.3o `overlay_bound_producer_files` 并进 `inputs`（含 seed 路径 + P2.3t `tests/` 新文件）；
2. `create_attempt` 记下这些 inputs；
3. `_bind_workspace`：`retry_of` 时 `previous = …/retry_of`（`:3671-3672`），`WorkspaceManager.create` 先 `_copy_tree(previous)`（`workspace.py:321-322`），再写 seed、再 `write_bytes` overlay（`:347-348`）；
4. `_bind_agent`（`:3848-3857`）`list_files()` 快照。

因此 **overlay 在快照之前**，预铺源码（及 overlay 的 `tests/`）在 `read_only_existing` 里，不能被改写。用户点名的 P0 候选不成立。

`list_files`（`workspace.py:224-236`）：只列普通文件；跳过 `__pycache__` / `.pytest_cache` / `.git`；**含隐藏文件**（探测 `.hidden.py` 被拒）；符号链接既不列入、`create` 遇 symlink 直接拒绝。路径复用 `_canonical` + `casefold`：探测 `./metrics/collector.py`、`metrics//collector.py`、`Metrics/Collector.py` 均 `read_only_existing_file`；`metrics/foo/../collector.py` 先被 `resolve` 打成 `workspace_error`（禁止 `..`），文件不变。

与 journal「快照 = seed ∪ overlay，与 `read_only_rewrites` 的 `initial` 同一集合」**在 retry 上不一致**：`initial` 只有 seed + upstream（`event_handler.py:5297-5305`），不含上一 Attempt 新写的 `REPORT.md`；`list_files()` 在拷贝 previous 之后会含这些产物。见 P1-1。

`WorkspaceError` 时快照落成 `()`（`:3858-3859`）是 fail-open；`list_files` 本身不抛，实际几乎走不到。P2。

### (b) 绕过面 —— 工作区写入口只有 `workspace_write_file`；新文件（含 `tests/`）是允许的

Worker 工具：`workspace_read_file` / `workspace_write_file` / `workspace_list` / `run_tests`。`run_tests` 在 throw-away `exec_copy` 里跑 pytest，写不回 attempt 树（`tool_gateway.py:835-846`）。`apply_patch` / `workspace_apply_patch` 对只读叶从 `effective_tools` 去掉，且 `execute()` 无实现（会 `unknown_tool`）。无删除/重命名工具。AppWorld 的 `appworld_execute` 动模拟世界，不写工作区源码。

写到**新路径**（报告、声明端口、甚至 `tests/test_new.py`）网关放行——这是声称的「新文件允许写」。P2.3m 只拦 `initial` 里哈希变化的路径，新文件不会 `ResultRejected`。P2.3t overlay 会把生产者 `tests/` 预铺给下游，所以只读叶若把新测试写成产物，可能污染下游。提示词 v4 / synthesizer v7 禁止这样做，工具层不拦。P2，不是本片声称的漏洞。

### (c) 被拒后的模型侧 —— 消息明确；无专用连拒上限；P2.3m 仍在

拒绝文案（`tool_gateway.py:653-657`）：该叶只读、不要改已有文件、把发现写进声明端口或 `REPORT.md`。第一 Attempt 路径清楚。

连拒：`count_tool_calls` 默认只计 `outcome=succeeded`，事前拒绝**不计入** 48 次 tool cap；同 Attempt 上限是 `max_model_calls_per_turn=24`。没有「连续 `read_only_existing_file` N 次停手」的专用门。比原来白烧整次 Attempt ×2 再修轮好，但仍能烧满一轮模型调用。P2。

P2.3m 同哈希规则未改（`read_only_rewrites` / `MAX_READ_ONLY_REWRITE_REJECTIONS=2`）。`test_a_direct_workspace_rewrite_is_still_refused_at_collection` 绿：绕过工具的直写仍 `ResultRejected{read_only_leaf_rewrote_workspace}`。

### (d) 写型叶不受影响 —— ✅；与 `_protected_seed` 无新冲突

`read_only_existing` 默认 `()`；写型叶 `read_only_leaf()` 为假，intent 不加键。`test_a_writing_leaf_is_not_blocked_from_rewriting_existing_files` 与 e2e 里 apply-patch 步改 `metrics/collector.py` 均绿。

### (e) legacy —— ✅

`effective_tools(..., read_only_leaf=False)` 默认不裁清单。DAG 绑定不设 `read_only_existing`（`test_a_legacy_binding_without_read_only_existing_still_writes`）。AppWorld 分层 Worker `tool_names` 仍含 `appworld_execute`（`('workspace_read_file', 'workspace_write_file', 'workspace_list', 'appworld_execute', 'knowledge_list', 'knowledge_read')`）；只读叶裁的是 patch/apply 名，不动 `appworld_execute`。仓库内无独立 `selftest_runner` 文件；selftest 口径由 `effective_tools` 四向交集测试钉住。

**P1-1. retry 快照含上一 Attempt 产物，只读叶无法更新自己的报告**
