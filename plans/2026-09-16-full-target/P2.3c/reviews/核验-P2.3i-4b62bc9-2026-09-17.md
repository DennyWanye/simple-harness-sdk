## 二、重点缺陷排查（任务书 2a–2f）

### (a) 可修正 / 不可修正划分

逐个产生处核对（`registry.py` 步 1 L1440–L1580、步 2 L1590–L1725、步 3 L1780–L1870、准入前 L905–L945）：

- **`MALFORMED_DEFINITION`** 六个产生处：`reject_executable`（belt-and-braces；模型回复经 `parse_method_proposal → MethodContract.from_json`，`contracts/htn.py` L352/L411/L528 已在构造期拒绝可执行内容 → `ContractError → SynthesisReplyUnreadable`，此处**到不了**）、无步骤、`reuse_policy` 与类型的 `read_only/effect_identity` 冲突（见 P2-3）、argument 读未声明参数 / 未知步 / 自身步输出、criterion link 指向未知步。除 P2-3 外全是「包里已有正确值」的引用/形状。**划分成立。**
- **`FORM_MISMATCH`** 两个产生处：步 form 与类型不符（`operators[].form` 在包里）、goal type 是 primitive（模型改不了 goal；但 `goals_needing_method` 只对 compound 提问，实际到不了；即便到了也只多花一问、有界）。**划分成立。**
- **`ROOT_COVERAGE_GAP`**：`goal_signature.coverage_criteria` / `required_criteria` 在包里，是「漏链」不是「语义错」——协议本来就只查 link 的 parent id 集合与 child_step 存在性，不查语义；重问不比第一问多放宽任何东西（见 P2-4 的边角提醒）。**划分成立。**
- **I18 / §18.5**：I18 = `ValidityWitness.decision=USABLE ⇒ truth=TRUE`（P1.1 journal L52），本片完全不碰谓词/真值；`UNKNOWN_PREDICATE`/`PREDICATE_TYPE_ERROR` 归不可修正（包里无谓词清单，`build_request` L535–L555 确认）。§18.5「状态由注册服务写」：`MODEL_CLAIMED_STATUS` 归不可修正，重问的第二次回复仍走同一 `apply_synthesizer_reply`（author 锁 MODEL）。**没有放宽。**「猜到准入为止」不成立：上限仍 2 问，且第二问只带协议原话 + 「只改点名处」。

## 四、问题清单

无 P0 / P1。

### P2-1 `MethodSynthesisReplyRejected` 的「键按 ordinal」不可观测（测试盲区）
- 位置：`src/agent_orchestrator/orchestrator/hierarchical_dispatch.py` L3073 `key=f"{mission_id}:{goal_task_id}:{int(ordinal)}"`。
- 复现：变异 MC 把键改成不含 ordinal，`test_synthesis_rejection_reask.py` + 两个相邻文件 40 用例全绿。原因：上限 2 问时该事件只会以 ordinal=1 写一次，第二问被拒走 `RoundRecorded`，键的 ordinal 部分永远只有一个取值。
- 建议：给 `record_synthesis_reply_rejected` 加一条单元测试（同 goal 写 ordinal 1 与 2 → 两条事件；同 ordinal 写两次 → 幂等只一条），与 `record_synthesis_reply_unreadable` 对称。不改代码。

### P2-2 第二问开出与第一问事件写下之间的崩溃窗口
- 位置：`event_handler.py` L4084（`_create_synthesizer_intent` 提交）→ L4095（`record_first_ask()` 写事件）是两个事务。
- 复现（推理）：进程在两者之间崩溃并重启：第二问意图已持久（CLAIMED/PENDING），第一问已 FAILED，但日志里没有 `MethodSynthesisReplyRejected/Unreadable{ordinal:1}`；Host 收据看到「问了两次」却没有「为什么」。重启后 `_maybe_request_synthesis` 不会重取（ordinal-1 subject 仍在），流程本身不受影响。
- 建议：把「创建第二问意图 + 写第一问事件」放进同一 `store.transaction()`（`create_service_intent` 已在事务内，可传一个 `on_success` 事件或在 `HierarchicalDispatch` 提供 `open_second_ask()` 一步完成）；或在 `_collect_synthesizer` 入口按「第二问意图已存在但无第一问事件」补写。不阻塞合并。

### P2-3 `MALFORMED_DEFINITION` 的 reuse_policy 变体，包里没有它需要的事实
- 位置：`registry.py` L1541–L1552（`reuse_policy` 非 NEW_WORK 且类型 `not read_only and effect_identity is None`）；`synthesis.py` `_offers` L608–L625 只输出 `side_effect_kind`，不输出 `read_only`/`effect_identity`；v3 提示词的「只改点名处」清单不含 reuse_policy。

- 建议：要么 v3 清单加一句「reuse_policy 与类型冲突时删掉该字段」，要么把这一变体从可修正里剔除（按 detail 前缀分辨），下一片择一。

### P2-4 `ROOT_COVERAGE_GAP` 重问的边角提醒（不是缺陷）
- 位置：`registry.py` L1852–L1862；v3 提示词「criterion_links … 只能引用你自己 steps 里的 local_id」。
