# 第 8 步验收标准（MUST 7 条 = ORCH-BUILD §10.3 S8-01～07）

| ID | 场景 | 必须观察到的结果（纲要原句 → 本步可判定形式） | 判定 |
|---|---|---|---|
| S8-01 | 指定一次已完成 Mission | 可查看最终产物依赖链及真实费用归属 → 归因报告列出最终产物（路径与内容哈希）→ 产出它的 Task / Attempt / Agent / 角色 / 模型 / prompt 版本 → 使它通过的验证层；多 Task 时包含合并进集成树的上游产物与知识路径；未进入成功路径的 Attempt 单列为探索消耗；路径内 + 路径外 + 服务调用的 tokens 之和等于该 Mission 已导入用量总和，金额在未定价部署下为 null 并注明 | `test_attribution.py::test_s8_01_*` |
| S8-02 | 回放重复事件 / 崩溃记录 | 得到相同正式状态；外部调用数不增加 → 对已完成 Mission 回放：投影出的正式状态（plan D8-2' 字段集）覆盖率 = 100% 且逐字段与库快照一致（覆盖 static-dag、knowledge-sharing、dynamic-dag、approval-action 与一次失败的 Mission）；把事件流重复投递一遍（同 event_id）结果不变；在崩溃时刻复制的库上，前缀投影等于该副本快照，恢复完成后回放等于最终快照；回放前后 provider / 连接器 / pytest / Critic 调用计数不变，原库主文件、`-wal`、执行库 sha256 不变，只读目录下照样成功；replay 模块不导入 runtime / providers / 确定性验证 | `test_replay.py::test_s8_02_*` |
| S8-03 | 比较两个策略 | 使用相同任务集 / 预算边界，输出两者指标和失败案例 → 评测计划里两个策略跑同一组 case、同一预算上限、各 N 次试验，每次运行的幂等键为 `eval:<plan>:<strategy>:<case>:<trial>`、Mission id 两两不同、各在独立新目录与库（目录已存在则拒绝）；报告对两个策略各给出成功率（带样本量）、耗时分布、tokens / 金额（或 unpriced）、验证通过率、知识复用、重复率、失败原因与失败样例；比较用 Fisher 精确检验与 Wilson 区间，差异不显著写"证据不足"，fixtures 写"不适用（fixture）"；超时 / 脚手架错误记 `harness_error` 不计入分母；有隐藏 oracle 的 case 给出验证误判率 | `test_evaluation.py::test_s8_03_*` |
| S8-04 | 移除 Critic 或 Blackboard 做消融 | 报告关闭了什么、哪些变化可观察；不预设一定变差 → 消融 `critic`：有效验证政策去掉 critic_review（层记 `NOT_REQUIRED` 且 `detail.ablated=true`）、Critic 调用数为 0、PASS 标注"消融政策下的 PASS"、带自由文本准则的 case 拒绝与 critic 消融组合；消融 `blackboard`：`KnowledgeUsed = 0`；报告列出关闭项与观察到的指标差异（不论方向）；请求消融权限 / 幂等 / 审批 / 确定性验证层、或经策略配置覆盖预算 / 部署政策 / 连接器被拒绝；评测运行只允许测试连接器 | `test_ablation.py::test_s8_04_*` |
| S8-05 | 历史 Trace 不完整 | 报告覆盖不足，不能伪造完整 Lineage → 删去部分事件或用缺字段的旧事件回放：覆盖率 < 100%，缺口逐项列出（缺哪个对象的哪个字段、违反了哪条结构性不变量、与库比对缺失哪些事件 id），这些字段为 `not_covered` 而不是库里的现值；归因遇到缺失的记录时标注断点，不补边 | `test_replay.py::test_s8_05_*`、`test_attribution.py::test_s8_05_*` |
| S8-06 | 新模型重跑旧任务 | 标记为新 Evaluation 与新成本，不覆盖旧 Mission 事实 → 从本版本演示产生的旧证据目录派生 case（spec 哈希与旧库 `MissionCreated.spec_hash` 一致才允许）、改写幂等键、换 runtime profile（或模型名）重跑：新 Mission id、新目录与新库、新费用；报告写明 `derived_from`（原 tenant / key / Mission id / 快照哈希）；旧库文件 sha256 与旧快照在运行前后相同 | `test_evaluation.py::test_s8_06_*` |
| S8-07 | 检索 / Prompt / 模型版本变化 | 报告明确列出版本差异，能够复现配置来源 → 两个策略快照之间的 `snapshot_diff` 逐项列出差异与来源（模块与常量名 / 配置字段）——覆盖模型名与 profile、消融列表、白名单配置项，以及代码中版本常量（prompt / retrieval / allocator）改变时的差异；快照枚举全部配置字段，新增字段未归类时测试失败；评测报告对每个策略给出快照哈希；同一配置两次快照哈希相同 | `test_policy_snapshot.py::test_s8_07_*` |
