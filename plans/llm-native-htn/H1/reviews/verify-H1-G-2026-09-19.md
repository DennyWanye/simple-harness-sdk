## 4. 等价性与有意差异

独立构造（不引用实施者测试夹具的 JSON 字面量）旧 `<plan_revision_proposal>` 文本，经现网 `parse_plan_proposal` 后与适配结果做 `canonical_json` 字节比较：

- `REFINE`：通过。
- `REPAIR/REPLACE_METHOD`：通过（含 `retire_method` 在前、`request_stop_then_reconcile`）。
- `WAIT` / `NO_CHANGE` / `DECLARE_BLOCKED`：无旧提案对象可比；断言 `proposal is None` 且 durable 字段与载荷一致。
- `BIND_EXISTING_GOAL` / `REPAIR/PROPOSE_SUCCESSOR`：按裁定不再要求与现网操作等价；适配器拒绝。

实施者声明的有意差异及本轮判断：

| 声明 | 判断 |
|---|---|
| `proposal_id` / `mission_id` / `expected_plan_revision` / `read_set` / `trigger_refs` / 运行中工作策略不从模型决定读取 | 成立。`_proposal` 只读 `AdapterContext`；策略由适配器写入。 |
| 方法引用用准入解析后的 `MethodRef`，不用模型修订号 | 成立。`_method_ref` 取 `admitted.method_refs[0]`。 |
| 模型 `bindings` 里的同名键只保留为领域参数，不覆盖提案顶层字段 | 成立。独立构造把 `mission_id` / `expected_plan_revision` / `proposal_id` / `principal` / `authored_by` 放进 bindings，提案顶层仍来自 context。 |
| 未启用类型（含追加裁定的绑定/后继）抛 `ContractError` | 成立。 |
| `DurableOnly` 携带 `canonical_hash` | 成立。 |
