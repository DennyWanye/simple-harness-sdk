# H1-G 独立核验报告（2026-09-19）

## 结论

判定：**不可合**。

存在 P0：适配器虽生成了现网 `BindSharedGoalOperation` 与
`ProposeSuccessorOperation`，但现网 `HierarchicalDispatch.compile_proposal()` 只接受恰好一个
`RefineOperation`、以及至多一个 `RetireMethodOperation`；这两类适配结果进入现网编译器都会
在编译前被拒绝。因此第 44 节映射不能形成可执行主链，且未满足本片明确要求的“展开与共享绑定
各跑通一次”。

另有 P1：`WAIT` 的 `wait_for` 内容没有被现有测试断言；把它清空的变异存活。`DurableOnly`
当前根本没有 `canonical_hash` 字段，故“durable_only 丢 canonical_hash”不是可施加于当前基线的
变异，而是一个现状缺口，已单独备案。

## 逐条问题

### P0-1：共享绑定提案无法通过现网编译

- 适配器位置：`src/agent_orchestrator/planning/decision_adapter.py:307-325`，将
  `BIND_EXISTING_GOAL` 生成 `BindSharedGoalOperation`。
- 编译器位置：`src/agent_orchestrator/orchestrator/hierarchical_dispatch.py:3784-3799`，只统计
  `_is_refine()` 与 `_is_retirement()`；共享绑定导致 `1 operation(s) of which 0 refine and 0 retire`。
- 复现：在现有 `_rejected_open()` 测试世界中构造 `SHARE_ACTIVE` 决定，调用
  `adapt_admitted_decision(...).proposal` 后再调用
  `world.dispatch.compile_proposal(mission_id, proposal, world.network())`。
- 实际结果：`ContractError`，原文为：

  ```text
  proposal 'pd-compile-bind' carries 1 operation(s) of which 0 refine and 0 retire; this slice assembles exactly one refinement per round, optionally replacing the method instance adopted at that same occurrence with one retire_method (a merged delta is re-validated as a whole, §24.1 decision 8)
  ```

### P0-2：提后继提案同样无法通过现网编译

- 适配器位置：`src/agent_orchestrator/planning/decision_adapter.py:288-304`，生成
  `ProposeSuccessorOperation`。
- 同一编译器合同会将其计为 `0 refine / 0 retire` 并拒绝；现有源码中没有对
  `ProposeSuccessorOperation` 的编译分支。
- 复现使用同一 `_rejected_open()` 测试世界和 `REPAIR/PROPOSE_SUCCESSOR` 决定。
- 实际结果：同样为 `ContractError`，首行原文为：

  ```text
  proposal 'pd-111111111111111111111111' carries 1 operation(s) of which 0 refine and 0 retire; this slice assembles exactly one refinement per round, optionally replacing the method instance adopted at that same occurrence with one retire_method (a merged delta is re-validated as a whole, §24.1 decision 8)
  ```

### P1-1：WAIT 载荷内容测试缺口

- 位置：`tests/orchestrator/full_target/test_planning_decision_adapter.py:269-283`。
- 变异 M10 将 `wait_for=payload.wait_for` 改为空元组后，定向测试仍为 9 passed。
- `WAIT` 的 durable 信号因此缺少可分辨的回归断言；建议至少断言 `wait_for` 与决定载荷逐项相等。

### P1-2：durable-only 未携带 canonical_hash

- 位置：`src/agent_orchestrator/planning/decision_adapter.py:125-133`。
- `DurableOnly.__annotations__` 中没有 `canonical_hash`，而输入
  `AdmittedPlanningDecision` 在 `:487-495` 明确携带 `canonical_hash`。
- 因基线已经没有该字段，无法诚实地执行“删除 canonical_hash”变异；这是缺失而非被测试杀死的
  变异。补遗要求新事件可携带 canonical hash，后续持久化接线若依赖适配结果，当前形状无法传递它。
